# Prompt to explainer

Run the production for the user. The deliverable is a playable film. Use the supplied duration, language, aspect ratio and style. For a bare topic, use a 30-second English portrait short at 30 fps in the dark metallic style. Keep project files in a new writable output directory. Run tools locally with free assets and speech. Check [Remotion eligibility](https://www.remotion.dev/license) for the intended use. If a paid license would be needed, offer the local Three.js/browser and FFmpeg path before scaffolding.

1. **Scaffold.** Copy `assets/template/` into the new project and run `npm ci` there. Set the composition geometry and duration in src/index.jsx. Select [dark metallic](styles/dark-metallic.md), [isometric](styles/isometric.md), or write a project-local style brief using the same fields for a new look. Put the selected palette, camera, lighting, typography and motion in a shared theme. With a supplied reference, inspect representative frames and transitions first.
2. **Research.** Assign one research agent. Deliver research.md with a short explanation, limits and a list of numbers and analogies. Give every factual item a direct primary-source URL. Include units, conditions and dates for numbers. For an original analogy cite its underlying mechanism and identify where the comparison breaks. Omit unsupported examples. Assign claim IDs that script and storyboard can reference.
3. **Narration & timeline.** Write narration.txt first. For the macOS voice and local forced-alignment recipe, read [local speech](references/local-speech.md). Synthesize final English or requested-language speech locally with a timing-capable voice, or align the final WAV to the script with a local forced aligner. Save actual word start/end seconds from synthesis or alignment in words.json. Check normalized transcript order against the script and listen around proper names and pauses. Use scripts/timeline.py on the skill path (arguments: words.json, fps, total frames, output JSON). Input is an array of objects with word, start, end. Use its half-open frame intervals for speech highlights and cues. Group words at natural phrase breaks, preserve the spoken text, and export subtitles.tsv with startFrame, endFrame, text. Rewrite and re-synthesize if speech overruns. Re-align after any edit to timing. Keep narration.wav in public/ and mount Audio using staticFile once on the master timeline.
4. **Storyboard.** One row per shot in storyboard.tsv: ID, chapter, group, [start,end), spoken beat, claim ID, visuals, motion, hero element, lighting. Cover frame zero through the exclusive end without gaps or overlaps. Use actions to explain the idea and allow time to read the result.
5. **Overlays & primitives.** Implement shared title, chapter cards, HUD, pipeline/progress rail, captions and 2–5 original topic icons. Keep text and icon layers outside the 3D camera. Define safe margins and caption placement in the theme. For a single chapter, combine the chapter card and opening title. Map the rail to actual stages or chapters.
6. **Pilot.** Assign one pilot agent the first shot group, shared theme and storyboard. Render the opening group then render the first min(30 seconds, film duration) with final voice, captions and overlays. If the group ends earlier, give that agent the extra shots needed for the pilot. Show the playable cut and collect the user's look judgment before distributing remaining groups, unless they explicitly request autonomous delivery. Reuse accepted pilot shots.
7. **Parallel build.** Dispatch remaining work in groups of 5–7 shots per agent (short final group allowed), in waves within available slots. Assign each worker a separate group file and its storyboard rows. Each shot is a pure function of local frame, theme and immutable inputs. Sequence offsets belong to the coordinator. Use seeded randomness, explicit camera transforms and frame-driven Three.js animation. Workers return exports, covered frame IDs and representative stills. Coordinator owns shared overlays, integration and audio. Skip empty groups. If agents are unavailable, explicitly record serial execution.
8. **Render.** Assemble sequences and run npm run render in the project. Decode the entire MP4. Use ffprobe to verify video/audio streams, dimensions, exact frame count and duration. Run FFmpeg blackdetect and freezedetect, and signalstats with metadata output to measure frame luminance. Save thresholds, intervals and per-shot min/mean luma in metrics. Compare flags with planned holds, fades and the chosen palette. Sample chapter boundaries and caption transitions visually; frame statistics alone cannot certify readable captions.
9. **QC & fixes.** Assign one independent QC agent per chapter to inspect its encoded frames, listen to the audio, compare claims against research, inspect subtitle timing, clipping, safe areas, motion and continuity. Return timestamped issues with expected result and severity. Assign fix agents by affected group, re-render impacted cuts, then render and verify the delivered master. Review joins on both sides of every change. Deliver the playable MP4 and short notes with style, duration, resolution, voice, source list, metrics and any unresolved limitations. A short approved pilot covering the whole film goes directly to render verification and QC.
